# QMods badges 2.1.1 — установка внутри qmods.ru

Достаточно доступа к корню сайта и его каталогам. Доступ за пределы сайта, SSH, настройка переменных окружения и SQLite не нужны.

Требования: PHP 8.1+ с curl, HTTPS, локальная файловая система с блокировками и переименованием файлов, исходящий HTTPS к api.vk.ru. PHP должен исполнять файлы с расширением .php, включая вложенные каталоги.

## Обновление установленного сервера 2.1.0

Замените **только `api/vklite/badges.php`** новым файлом из архива. Папку `_data` и файл state.php не удаляйте и не заменяйте: там хранятся подключённые значки. Код 2.1.1 читает прежнее хранилище без преобразования.

Исправлена совместимость с PHP 8.5: убран устаревший `curl_close()`, вывод PHP-диагностики в HTTP-ответ отключён, перед JSON очищается собственный буфер вывода. На хостинге PHP 8.5 предупреждение раньше попадало перед JSON и ломало подключение значка в клиенте. После замены health должен показывать `server_version: 2.1.1`.

## Загрузка

1. Распакуйте архив **в корень qmods.ru**, сохраняя пути. Должны получиться:

   ```text
   api/vklite/badges.php
   api/vklite/config.php
   api/vklite/config.example.php
   api/vklite/_data/.htaccess
   api/vklite/_data/index.php
   ```

2. Готовый `config.php` включён в архив: он указывает на `_data` рядом с API, редактировать путь не требуется. Если там уже есть старый `config.php` с путём за пределами сайта, замените его новым файлом из архива. Старые базы SQLite автоматически не конвертируются; при наличии такой базы сохраните её перед заменой сервера.
3. PHP должен иметь право записи в `_data`. Обычно достаточно прав 0700/0750 и владельца, под которым работает PHP; если PHP работает от другого пользователя, настройте запись средствами панели хостинга. Не ставьте 0777 на весь сайт. Если папка не существует, API попробует создать её сам. При FTP включите показ скрытых файлов, чтобы загрузить `.htaccess`.
4. Откройте `https://qmods.ru/api/vklite/badges.php?action=health`. Ожидается HTTP 200:

   ```json
   {"schema":2,"ready":true,"storage":"guarded_php","server_version":"2.1.1"}
   ```

5. **До подключения клиентов проверьте прямой доступ:**

   ```text
   https://qmods.ru/api/vklite/_data/state.php
   https://qmods.ru/api/vklite/_data/lock.php
   https://qmods.ru/api/vklite/_data/
   ```

   Все три адреса должны возвращать **403 или 404**, без содержимого базы. `state.php` и `lock.php` появляются после первого health-запроса. Если виден PHP-код или данные, выключите endpoint до исправления обработки PHP на хостинге. Не проверяйте только index.php: важно проверить state.php отдельно.

6. В VK Lite: Настройки → Значки QMods → разрешить загрузку общих значков → Подключить или обновить. Передача токена для проверки владельца требует согласия в клиенте. Адрес API и схема ответа прежние; новый APK для этой серверной версии не нужен.

## Как защищены файлы внутри корня

Данные лежат в `_data/state.php`, блокировка — в `_data/lock.php`. Каждый файл, включая временные файлы сохранения, начинается с PHP-кода, который отвечает 404, завершает выполнение и вызывает `__halt_compiler()`. Данные после этого блока PHP не выводит и не исполняет. Apache дополнительно закрывает всю папку через `.htaccess`. На nginx, где `.htaccess` не действует, защита опирается на исполнение PHP. Гарантировать защиту на сервере, который отдаёт PHP как обычный текст, невозможно — поэтому обязательна проверка прямых адресов выше.

Сохранение: блокировка отдельного файла, запись временного PHP-файла и атомарное переименование. Повреждённая база не обнуляется автоматически: API отвечает ошибкой, сохраняя файл для восстановления. Храните резервные копии **у себя на компьютере или в закрытом разделе панели хостинга**, а не как `state.php.bak`, `.zip` или `.txt` внутри публичного сайта. Для получения согласованной копии во время работы используйте функцию снимка/backup панели либо временно отключите endpoint и скачайте `_data`.

В базе: VK ID, цвет, время изменения, временные HMAC-хеши IP для лимита и серверная случайная соль. **VK-токены, cookies, пароли, имена и переписка не сохраняются.** Не включайте запись POST-тел в логи хостинга/WAF/APM. Пользовательский ID для подключения значка берётся исключительно из проверенного ответа users.get без user_ids, а не из заявленного клиентом ID.

Лимиты: 100 ID на lookup, 120 запросов в минуту с одного IP, до 100 000 записей значков и 16 МиБ файла состояния. Файловый вариант предназначен для небольшого сервера; для большой нагрузки потребуется отдельная БД. Чтение списка всех значков не предоставляется.

## Ошибки

- `curl_required`: включите curl для выбранной версии PHP в панели хостинга.
- `setup_required`: PHP не может создать папку/служебные файлы или записать данные. Проверьте владельца и права.
- `service_unavailable`: проверьте место на диске, права, целостность state.php и поддержку блокировок. Подробности намеренно не выдаются в публичный ответ. Не удаляйте базу ради сброса ошибки.
- `https_required`: запрос пришёл без HTTPS. Если TLS заканчивается на прокси, хостинг должен передавать корректный признак HTTPS в PHP. API не доверяет произвольному X-Forwarded-Proto из Интернета.
- `vk_unavailable`: хостинг не смог обратиться к VK; проверьте исходящий HTTPS и сертификаты. TLS-проверку не отключайте.
- `vk_auth_failed`: VK отклонил токен; наличие доступа к сайту не расширяет права сессии VK.
- `rate_limit`: подождите минуту. Заголовок Retry-After содержит задержку.

Маршруты и схема совместимы с VK Lite 0.24.0 и 0.25.0: GET action=lookup&ids=…, GET action=health; POST action=enroll/remove с access_token и необязательным style. Токен передаётся только в POST, не в URL.

Размещение на qmods.ru выполняет владелец сайта; агент не менял работающий сервер.
