# QMods badges — установка

PHP 8.1+; расширения curl и pdo_sqlite. Веб-сервер должен обслуживать PHP через HTTPS.

1. Поместите `badges.php` по адресу `https://qmods.ru/api/vklite/badges.php`.
2. Создайте отдельную папку **вне public_html/document root**, доступную PHP для записи, например `/home/site/private/vklite-badges`, с правами 0700.
3. На обычном хостинге скопируйте `config.example.php` в `config.php` рядом с `badges.php` и укажите полный путь из шага 2. Либо задайте PHP/FPM переменную окружения `QMODS_BADGE_STORAGE` с абсолютным путём к этой папке. В FPM можно задать `env[QMODS_BADGE_STORAGE] = /home/site/private/vklite-badges`. В Apache используйте SetEnv в конфигурации виртуального хоста. При использовании окружения перезапустите FPM/перечитайте конфигурацию. Папку внутри document root API не примет: это защищает SQLite от случайной публикации.
4. Откройте `https://qmods.ru/api/vklite/badges.php?action=health`. Ожидается `{"schema":2,"ready":true}`. При `setup_required` проверьте путь и права.
5. В клиенте откройте «Настройки → Значки QMods»: проверьте локальный предпросмотр, разрешите загрузку общих значков и выберите «Подключить или обновить». Передача сессии требует явного согласия. Локальный показ не публикуется на сервере.
6. Не включайте запись POST-тел в логи/WAF/APM. Не публикуйте папку SQLite и rate-secret. Желательно дополнительно ограничить частоту запросов на уровне nginx/Apache.
7. Сделайте резервную копию SQLite обычными средствами хостинга. В базе нет паролей, VK-токенов, cookies, имён или содержимого переписки. Только VK ID, стиль значка и время изменения; кратковременный лимит хранит хеш IP.

Клиент при подключении/смене/удалении значка явно запрашивает согласие отправить токен на qmods.ru. Сервер сразу проверяет его через users.get, получает владельца из ответа VK (запрос без user_ids), затем забывает токен. Это не верификация личности, но заявить чужой ID без его токена нельзя. На клиенте серверный ответ сверяется с текущим аккаунтом.

Чтение: GET action=lookup&ids=ID1,ID2 (максимум 100). Изменение: POST action=enroll, style=qmods/blue/violet/green/amber, access_token=... . Удаление: POST action=remove, access_token=... . Токены никогда не передаются в URL. Нет API для выгрузки всех пользователей. Старые неподтверждённые заявки GitHub не переносятся.

Если HTTPS завершается на обратном прокси, настройте HTTPS=on в доверенной конфигурации веб-сервера/FPM. Не доверяйте произвольному X-Forwarded-Proto из Интернета. SQLite должен быть на локальном диске с поддержкой блокировок. Исходящий HTTPS к api.vk.ru обязателен; TLS-проверку не отключайте.

Сервер не размещён агентом на qmods.ru: загрузку и настройку выполняет владелец сайта. Если VK отклоняет токен этого типа, возвращается vk_auth_failed; фиктивное успешное подключение не показывается.
